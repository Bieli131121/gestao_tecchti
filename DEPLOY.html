Criar o projeto no Supabase ~15 min

1.1 Criar conta e projeto

Acesse app.supabase.com → clique em New Project.

# Preencha:
Name:        gestao-tecchti
Password:    (senha forte — anote!)
Region:      South America (São Paulo)
Aguarde ~2 minutos para o projeto inicializar completamente.

1.2 Pegar as credenciais

No painel do projeto: Settings → API

# Copie e guarde:
Project URL:   https://xxxxxxxxxxx.supabase.co
anon (public): eyJhbGciOiJIUzI1NiIs...
Nunca use a chave service_role no frontend — só a anon.

1.3 Criar os buckets de Storage

Vá em Storage → New bucket e crie os 4 buckets:

Buckets públicos

  • os-fotos — fotos das OS
  • logos — logo da empresa

Buckets privados

  • assinaturas — assinaturas digitais
  • pdfs — PDFs gerados
Para os buckets públicos: após criar, vá em Policies → Allow public access.
2

Executar o banco de dados ~5 min

2.1 Executar a migration SQL

No Supabase: SQL Editor → New query

Abra o arquivo supabase-migration.sql do projeto, copie todo o conteúdo e cole no editor. Clique em Run.

✓ O script cria 14 tabelas, triggers, RLS, funções e dados iniciais automaticamente.

2.2 Verificar as tabelas

Vá em Table Editor. Você deve ver estas tabelas:

profiles          clientes          servicos
categorias_servico  produtos        estoque_movimentos
orcamentos        orcamento_itens   ordens_servico
os_itens          os_checklist      os_fotos
financeiro_lancamentos              empresa_config

2.3 Inserir dados da empresa

Execute no SQL Editor para preencher os dados iniciais da TecchTI:

UPDATE empresa_config SET
  nome_fantasia      = 'TecchTI',
  razao_social       = 'TecchTI Soluções de Informática',
  cnpj               = '00.000.000/0000-00',
  inscricao_municipal = '000000',
  regime_tributario  = 'simples_nacional',
  cidade             = 'Garopaba',
  estado             = 'SC'
WHERE id = (SELECT id FROM empresa_config LIMIT 1);
3

Configurar e testar localmente ~10 min

3.1 Criar o arquivo .env.local

Na pasta do projeto, duplique o .env.example para .env.local:

cp .env.example .env.local

Edite o .env.local com os dados do passo 1.2:

VITE_SUPABASE_URL=https://SEU_PROJECT_ID.supabase.co
VITE_SUPABASE_ANON_KEY=sua_anon_key_aqui

3.2 Instalar e rodar

npm install
npm run dev
# Acesse: http://localhost:5173
Você verá a tela de login. O próximo passo cria o primeiro usuário.
4

Criar o primeiro usuário admin ~5 min

4.1 Criar o usuário no Supabase Auth

No Supabase: Authentication → Users → Add user

Email:    gabriel@tecchti.com.br
Password: (senha segura)
# Marque: Auto Confirm User

4.2 Promover a admin no banco

Copie o UUID do usuário (coluna User UID na lista de Auth Users). Depois execute no SQL Editor:

UPDATE profiles SET
  role = 'admin',
  nome = 'Gabriel',
  telefone = '48999999999'
WHERE email = 'gabriel@tecchti.com.br';
✓ Agora você consegue fazer login com acesso total ao sistema.

4.3 Testar o login

Acesse http://localhost:5173, faça login com o e-mail e senha criados. Você deve ver o Dashboard.

Se der erro de RLS, verifique se o trigger handle_new_user foi criado. Ele cria o perfil automaticamente ao criar o usuário no Auth.
5

Deploy na Vercel ~15 min

5.1 Opção A — Deploy pelo GitHub (recomendado)

1. Suba o projeto para um repositório GitHub (pode ser privado):

git init
git add .
git commit -m "TecchTI v1.1 — sistema completo"
git remote add origin https://github.com/SEU_USUARIO/gestao-tecchti.git
git push -u origin main

2. Acesse vercel.com → New Project → importe o repositório.

3. Na tela de configuração, Vercel detecta automaticamente que é Vite. Clique em Deploy.

5.2 Opção B — Deploy direto pelo CLI

npm install -g vercel
npm run build
vercel --prod
# Siga as instruções do CLI

5.3 Adicionar variáveis de ambiente na Vercel

No painel da Vercel: seu projeto → Settings → Environment Variables

VITE_SUPABASE_URL      = https://SEU_PROJECT_ID.supabase.co
VITE_SUPABASE_ANON_KEY = sua_anon_key_aqui

Após adicionar, clique em Redeploy para aplicar.

Sem essas variáveis, o sistema vai exibir erro de configuração na tela de login.

5.4 Configurar o domínio (opcional)

Vercel → Settings → Domains → adicione seu domínio personalizado.

Sugestão de subdomínio para a TecchTI: gestao.tecchti.com.br

O vercel.json já está configurado com SPA routing e headers de segurança. Não precisa alterar nada.
6

Cadastrar dados iniciais ~2h

6.1 Checklist de cadastros

  • Configurações → Empresa: preencher CNPJ, endereço, telefone, logo
  • Serviços: cadastrar todos os serviços que a TecchTI oferece com preços
  • Categorias: Câmeras e CFTV, Redes, Computadores, DVR, Suporte Remoto
  • Estoque: cadastrar câmeras, cabos, conectores, fontes e materiais em estoque
  • Clientes: importar ou cadastrar os clientes existentes
  • Financeiro: lançar contas a pagar e receber em aberto
  • Usuários: criar perfis para técnicos e outros colaboradores

6.2 Criar usuários da equipe

Repita o processo do passo 4 para cada membro da equipe, usando os roles corretos:

Roles disponíveis

  • admin — acesso total
  • tecnico — OS e clientes
  • financeiro — financeiro + relatórios
  • vendedor — orçamentos

SQL para mudar role

UPDATE profiles
SET role = 'tecnico'
WHERE email =
  'tecnico@tecchti.com';

6.3 Testar fluxo completo

Realize um atendimento completo de teste para validar o sistema:

  • Cadastrar um cliente fictício
  • Gerar um orçamento com 2 serviços → visualizar PDF → copiar link WhatsApp
  • Converter o orçamento em OS → abrir no celular
  • Na OS: marcar checklist → tirar uma foto → salvar assinatura → concluir
  • Lançar a receita no Financeiro → marcar como pago
  • Verificar se o Dashboard atualiza os KPIs
  • Gerar relatório do mês e verificar o PDF
✓ Se todos os passos funcionarem, o sistema está pronto para uso.

Problemas comuns

Erro: "relation profiles does not exist"

O SQL não foi executado completamente. Vá ao SQL Editor e execute o supabase-migration.sql novamente.

Login aceita mas redireciona para /login de volta

O perfil não foi criado. Execute no SQL Editor:

SELECT * FROM profiles WHERE email = 'seu@email.com';
-- Se vazio, o trigger não rodou. Insira manualmente:
INSERT INTO profiles (id, nome, email, role)
SELECT id, 'Seu Nome', email, 'admin'
FROM auth.users WHERE email = 'seu@email.com';

Upload de fotos não funciona

O bucket os-fotos não foi configurado como público. Supabase → Storage → os-fotos → Policies → Allow public access.

Deploy na Vercel dá erro de build

Verifique se as variáveis de ambiente foram adicionadas. O build falha com erro de import.meta.env se VITE_SUPABASE_URL não estiver definida.
